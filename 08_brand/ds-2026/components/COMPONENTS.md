# Component spec sheets · DS-2026 · Criterio Edition

Canonical component families. Each sheet gives **anatomy** (the parts, in DOM order),
**states**, **grid span and mode**, and the **rules** that are not negotiable.

Prefer one public bundle: `operations.css` for Setas OS, `market.css` for commercial/editorial surfaces, or `index.css` when both families are required. Do not stack public bundles.

---

## FOS-free conventions that apply to every component

- **No shadows.** `--shadow-none` is the only legal value. Depth is a rule.
- **No gradients, no glass, no floating panels.**
- **One identity accent per composition.** Semantic state colours may coexist.
- **Status is colour *and* word.** Never colour alone.
- **Mono labels are uppercase and tracked ≥ 0.15em.** Numeric data stays untracked.
- **Tap targets ≥ 44px** with ≥ 8px between them.

## 1 · Ficha / Lámina — `.sdp-ficha`

The archive object: one specimen, fully documented.

```
.sdp-ficha                    border: hairline (`--rule-hairline`)
├── .sdp-ficha__hd            species block  ‖  plate line + brand
│                             border-bottom: 2px INK
├── .sdp-ficha__body          2 columns, gap 32px
│   ├── .sdp-fig--plate       4:5, .frame-specimen
│   └── .sdp-ficha__prose     16px body, optional alert
└── .sdp-ficha__ft            3 cells, hairline dividers
    └── .sdp-ficha__cell ×3   __k (label) + __v (body)
```

**Span** 12 · **Mode** `archive` · **States** none (it is a document).

**Rules.** Header/footer separate with `--rule-heavy`; internal divisions are
hairlines. Footer is exactly three cells — presentación, preparación, precio.
Price uses `.sdp-ficha__v--price` (mono, body size) so it aligns as a figure.
Under 700px, body and footer become one column and cell borders move from
right to bottom.

## 2 · Lote card — `.sdp-lote`

The field object: one production lot at a glance.

```
.sdp-lote--{ok|warn|error}    border: 1px RULE
├── .sdp-lote__media          3:2 photo   (or __media--plate, 148px (`--plate-height`), for line art)
└── .sdp-lote__body
    ├── .sdp-species--compact common (22px) + latin
    ├── .sdp-lote__id         mono 16px — "LOTE 026 · HER-01"
    ├── .sdp-lote__status     __state (word) + __bar (4px) + optional day count
    └── .sdp-lote__meta       3 cells — sala / HR / CO₂
```

**Span** 3–4 · **Mode** `field`, also used in `control` asides.

**States** · `--ok` moss · `--warn` dark ochre marker (`--status-warn-marker`) + `--status-warn-text` · `--error` Coral 700. Raw Ochre 500 never carries a thin status rule.

**Rules.** The status bar is a 4px rule (`--bar-height`) — never a pill, badge, or rounded chip.
Line-art specimens use `--plate` (fixed height, `contain`, paper ground); photos
use the default 3:2 `cover`. Metadata is always exactly three cells.

## 3 · Receta card — `.sdp-receta`

```
.sdp-receta                   border: 1px RULE, padding 24px
├── .sdp-receta__hd           label + title  ‖  code + C:N
├── figure.sdp-fig--ingredient 64px (`--ingredient-size`) 1:1 + micro caption
├── .sdp-receta__ing          ingredient rows
│   └── .sdp-receta__row      64px key | name | %
│       + .sdp-receta__prop   2px rule, width = share
├── .sdp-receta__steps        <ol>, counter decimal-leading-zero
└── .sdp-alert                optional control note
```

**Span** 6 · **Mode** `field` · **States** none.

**Rules.** Proportion rules are filled with `SOIL`, not an accent — a recipe is
composition, not status. Percentages are mono so columns align. Step numerals
are generated by CSS counter; never hand-typed.

## 4 · Metric table — `.sdp-table`

**Span** 8–12 · **Mode** `control` · **States** per-cell:
`.is-ok` / `.is-warn` / `.is-error`.

**Rules.** `th` is mono 11px uppercase tracked over `--rule-heavy`. `td` is mono
13px with `tabular-nums`. `.num` right-aligns numerics; `.name` switches to
14px Sans so species names read as prose, with the binomial in Gaya italic.
Even rows take `PAPER_PANEL`. Table body never goes below 13px, and never
appears on field print at that size.

## 5 · Alert banner — `.sdp-alert`

```
.sdp-alert--{ok|warn|error}   border-left: 4px pigment; background: tint
├── .sdp-alert__icon          20px pictogram, inherits label colour (optional)
└── .sdp-alert__body
    ├── .sdp-alert__label     mono 11px upper tracked
    └── .sdp-alert__msg       14px Sans, INK
```

**Span** 4–12 · **Mode** any · **States** `--ok`, `--warn`, `--error`.

**Rules.** There is no "info" state — informational text is body text. In
`--warn` the label uses `WARNING_TEXT #866629`, never raw ochre (2.45:1). The message always sits in `INK` on the tint. Warning rules use `--status-warn-marker`, not low-contrast Ochre 500.

## 6 · Navigation bar — `.sdp-nav`

**Span** 12 · **Mode** any · **States** `[aria-current="page"]` on the last crumb.

**Rules.** Crumbs are **Sans**, not mono — this is reading text, not a code.
Separators `›` in `RULE`. Right-hand meta (date, site, time) is mono label.

## 7 · Telemetry tile — `.sdp-tele`

**Span** 3 · **Mode** `control` · **States** `--warn`, `--error`.

**Rules.** State recolours the **meter fill only**. The numeral stays `INK` —
a reading that has gone out of spec must not become harder to read than one
that is fine. Unit is a small mono span inside the value, never a separate row.

## 8 · Signage — `.sdp-sign`

```
.sdp-sign                     border: 3px INK
├── .sdp-sign__hd             SOIL ground, PAPER text (8.44:1)
│   ├── .sdp-sign__fn         brand / function, mono upper
│   └── .sdp-sign__room       display-02, 44px Gaya Bold
├── .sdp-sign__stats          3 cells, hairline dividers
│   └── __sk (label) + __sv (36px [`--size-data-xl`] mono) + 4px meter
```

**Span** 12 · **Mode** `field`, printed A2.

**Rules.** The only component that inverts. `PAPER` on `SOIL` is the sole

## 9–10 · Packaging — `.sdp-pack--front` / `.sdp-pack--back` / `.sdp-pack--multi`

**Front (Single Species)** — 3-row grid, centred: brand + origin / plate / naming block + net
weight. Species at **Gaya Bold 36px**, binomial at **Gaya Italic 18px**.

**Front (Multi-Species / Co-pack)** — `.sdp-pack--multi`, used **on its own, never with
`.sdp-pack--front`**: the archive cover scale (88px) is bound to `.sdp-pack--front
.sdp-species__common` and does not fit a half-width column. Centred 4-row grid:
brand + origin / badge + title / species columns / net weight.

```
.sdp-pack--multi
├── brand + origin
├── .sdp-pack__duo-badge        "SELECCIÓN CULINARIA": hairline box, --radius-sm, label scale
│   └── .sdp-pack__duo-title    co-pack title (Dúo Silvestre), --t-heading-02
├── .sdp-pack__species-grid     2 equal columns
│   └── .sdp-pack__species-col ×2   plate + name + binomial, hairline rule between columns
└── net weight
```

Common name at `--size-heading-01` (32px) Bold with a 2px `--accent-warm` rule; binomial at
`--size-small` (14px). Both wrap (`overflow-wrap`) instead of overflowing: each column has about
140px of usable width at 420px, "Shiitake" fits on one line and "Orellana Rosa" drops to two.
The front carries no lot, room or operator. `--accent-warm` only exists under
`data-mode="archive"`, so the co-pack front needs that mode.

**Back of a co-pack** — the normal `.sdp-pack--back` with `.sdp-pack__trace-list` holding one
`.sdp-pack__trace-row` per species (binomial in `__trace-sp`, then a `.sdp-statusline` with lot,
room and date). Never one merged traceability line.

**Back** — **flex column** so the traceability block pushes to the foot no
matter how long the copy runs. Sections are hairline-topped `__sect` blocks:
ingredients, preparación, conservación, trazabilidad + QR.

**Mode** `culinary` (or `archive` for specimen/editorial presentations; `archive` is required for
`--multi`) · **States** none.

**Rules.** The front carries **no operational codes**. No room name, no operator
name, ever reaches a customer surface — traceability goes through the QR. Grain
texture (`.grain`) is permitted on packaging and print only.

## 12 · Button — `.sdp-btn`

Variants: base, `--primary`, `--secondary`, `--accent`, `--danger` and `--field`. Coral 500 is decorative; text-bearing terracotta actions use the accessible `action.accent` role (Coral 700). Native `button` and `a` elements
share the same 44px minimum target. Supported states are hover, active,
focus-visible, disabled and `aria-busy="true"`. A busy button keeps its label so
the action does not become ambiguous.

## 13 · Field — `.sdp-field`

```
.sdp-field
├── .sdp-field__label       mono, uppercase, tracked
├── .sdp-field__control     min 44px (--tap-target-min); .sdp-input and .sdp-select share its rules
├── .sdp-field__hint        optional help, small, metadata colour
└── .sdp-field__error       only in --error; the "!" pictogram is generated by ::before
```

The visible label precedes the control; hint or error copy follows it. Placeholder text never
replaces a label.

**Error.** `.sdp-field--error` (also triggered by `aria-invalid="true"` on the control) says the
error three ways, never by colour alone: 2px `--status-error` border, semibold error text, and a
framed "!" pictogram. The label also takes the error colour. The border grows from 1px to 2px
with the padding reduced by 1px, so the control keeps its 44px minimum height and does not shift.
The consumer sets `aria-invalid="true"` on the control and links the message with
`aria-describedby`. The copy must say why it did not save and how to fix it. No shadows, no radii.

## 14 · Segmented selector — `.sdp-segment`

One row of options with exactly one selected, for a mutually exclusive choice such as
Hogar / Chef. It is not tabs (it does not switch a panel) and not a switch (it has two or more
named options). Built on **native radio inputs** inside `fieldset` + `legend`, not on
`aria-pressed`: exclusivity and arrow keys (which move and select) come from the browser, it works
without JavaScript, and screen readers announce "option 1 of 2".

```
fieldset > legend                   names the decision
└── .sdp-segment                    equal columns, hairline border
    └── .sdp-segment__option ×n     label, min 44px (--tap-target-min)
        └── input[type=radio]       native, same name for all, one `checked`
```

**States.** Selected: `--action-primary` fill, inverse text and bold weight (not colour alone).
Hover: `--surface-panel`. Keyboard focus: 2px `--focus-ring` outline with 2px offset
(`:has(input:focus-visible)`). Disabled: recessed fill and metadata text.
In `data-mode="field"` options are separated by 8px (`--space-1`) and each carries its own
hairline. Below 480px the control takes the full width.

**Consumer.** Declares `data-mode` on an ancestor, gives every radio the same `name`, writes a
`legend`, marks one option `checked`. Mockup: `mockups/segmento.html` (field and control).

## 15 · Operational reading — `.sdp-reading`

A reading is the canonical expression of an operational number:

```
.sdp-reading--{ok|warn|error|stale}
├── .sdp-reading__label       parameter / sensor key
├── .sdp-reading__value       numeric value in Ink (legacy alias: __val)
│   └── .sdp-reading__unit    ppm / °C / % / kg
├── .sdp-reading__target      target or expected band
└── .sdp-reading__meta        provenance + source + reading age
```

**Invariant.** State may recolour the left marker, target relation and status word,
but never the numeric value. A bad reading must remain at least as legible as a
normal one. `--stale` uses a dashed neutral marker; it means the evidence is old,
not that the measured value itself was bad.

## 16 · Operational state and provenance

`.sdp-state` answers **what is happening**; `.sdp-provenance` answers **how we know**. They may
appear together and must never be collapsed into a single badge. They share one box: panel
background, hairline border, a left rule of `--marker-width`, and an 11px mono uppercase tracked
label. `.sdp-state` lives in `components/shared/view-state.css`, `.sdp-provenance` in
`provenance.css`.

`.sdp-state` variants: `--active` (ok marker), `--attention` (warning), `--blocked` (warning,
dashed marker, the quarantine style), `--failed` (error marker and error background),
`--unavailable` (neutral, dotted marker). The marker also differs by line style (solid, dashed,
dotted), so state is colour, line **and** word. The consumer writes the visible word.

`.sdp-provenance`: measured, calculated, estimated, target, manual, simulated or pending.
New markup uses the attribute API, for example
`<span class="sdp-provenance" data-provenance="measured">MEASURED · SCD30 · 3 MIN</span>`.
The glyph is generated from the domain token (`--provenance-measured-symbol`);
visible wording remains application-localized. Legacy `.sdp-provenance--*`
modifiers are compatibility aliases for marker styling only.

## 17 · View state — `.sdp-view-state`

Loading, empty and error at screen level: one situation, one message, one next action.

```
.sdp-view-state--{loading|empty|error}   panel, hairline, left rule of --bar-height
├── .sdp-view-state__label               11px mono uppercase
├── .sdp-view-state__title
├── .sdp-view-state__body                max 60ch
└── .sdp-view-state__actions             .sdp-btn controls
```

`--loading`: dotted marker and words, **no animation, no skeleton**. Use `role="status"` and
`aria-busy="true"`; if saved data is on screen, say it is the saved data. `--empty`: recessed
background; it must say what to do next and put that action in `__actions`.
`--error` takes `data-cause`: `network` (dashed warning marker; actions: keep working offline,
retry) or `server` (solid error marker; actions: retry, report). Without `data-cause` it behaves
as a server failure. Errors use `role="alert"`; loading and empty use `role="status"` or
`aria-live="polite"`. Each cause carries its own label.

In `data-mode="field"` padding drops to `--space-2`, and the controls in `__actions` are at least
`--tap-target-min` high with 8px between them. The consumer supplies the Spanish text, roles and
buttons. Mockup: `mockups/view-state.html`.

## 18 · Thermal label — `.sdp-thermal` / `[data-print="thermal"]`

Field label for the Phomemo M110: 203 DPI (8 dots/mm), 1-bit, no greys. File:
`components/operations/thermal.css`. Physical box 50 × 30 mm, declared with
a **named page**: `@page thermal { size: 50mm 30mm; margin: 0 }` plus `page: thermal` on the
container. The page must stay named — a bare `@page` here would be global, so every consumer that
loads this bundle and prints anything at all would print on 50 × 30 mm paper. Another roll size
overrides `@page thermal` and the container's width and height.

```
.sdp-thermal                     50 × 30 mm, white paper, black ink, 0.5 mm frame
├── .sdp-thermal__lot            lot code, weight 800
├── .sdp-thermal__species        0.5 mm rule above
├── .sdp-thermal__date           0.5 mm rule above
└── .sdp-thermal__bar            solid black status bar, 1.5 mm
```

**Rules.** Everything resolves to black on white (the `black` and `white` keywords, no tokens, no
tints) with `filter: contrast(400%) grayscale(100%)` and `print-color-adjust: exact`. Rules are
0.5 mm (4 dots): a 1px CSS rule is 0.125 mm, one dot, and is lost. Type uses the `lot-code-print`
role (6 mm mono) and each row keeps a minimum height of `--print-code-x-height` × 2; never
micro-print. Rows do not wrap and clip, roughly 12 characters per row in the 47 mm of usable width.
State is the solid bar, not colour. No shadows, no radii. Each label breaks the page on print.

**Consumer.** Writes the text of each row and loads `tokens/tokens.css` first.
**Mode** `field` · **States** none. Mockup: `mockups/etiqueta-termica.html` (hides the banner and
notes on print). Pending: verify the 0.5 mm rule and 1.5 mm bar on paper with the M110.

## 19 · Editorial devices — `.ed-*`

Typographic devices for archive surfaces, in `components/market/archive.css`. They have no
interaction and no states.

| Device | Parts | Use |
|---|---|---|
| `.ed-eyebrow` | none | Uppercase over-label, tracking 0.2em |
| `.ed-sec` | `__k` (label), `__h` (heading) | Section opened by an editorial rule |
| `.ed-note` | `__k` | Margin note, `--measure-note` (22ch), hairline above |
| `.ed-div` | `__m` (mark) | Divider with a hairline on each side of a centred mark |
| `.ed-cartouche` | `__n` number, `__l` italic caption, `__d` description | Figure cartouche |
| `.ed-cols` | none | Two-column text with a hairline between columns |
| `.ed-folio` | none | Folio line with editorial rule above |

**Drop cap.** One rule (3.05em, Black, `--ink`) serves three cases: automatic on the first `p` of
`.sdp-ficha__prose` and on the first `.sdp-pack__sv` of the first `.sdp-pack__sect` of a pack back,
both only under `data-mode="archive"`; manual with `.ed-drop`. Never on `.ed-lede`.

**Figure caption.** Under `data-mode="archive"`, `.sdp-fig__ref` becomes editorial italic, 17px.
`.ed-cartouche__l` uses the same 17px; there is no size token for it yet.

Mode `archive`, except the structural `.ed-*` devices, which do not depend on the mode. Mockup:
`mockups/editorial.html`.
